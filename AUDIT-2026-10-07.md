## Findings and what was done

### HIGH — AI guide could invent income limits (FIXED)
Probe: "I make 68000 with 4 people in 30513. Do I qualify?" → guide answered **$105,700 / $53,300, "page 9"**. Real FY2026 figures for Fannin County are **$122,800 / $61,600, page 71**. The model ignored its "never guess" rule when the browser did not hand it tool results.
Fix (server side, `functions/api/guide.js`):
- Before the model runs, the server finds the ZIP in the message or on-screen context, runs the same `check()` the site uses, and injects an exact FACTS block (limits for 1–4 and 5–8 people, page, area type, the household's verdict).
- After the model runs, any dollar figure ≥ $10,000 or any "page N" that is not in the facts, prior tool results, or the person's own words is treated as a guess and the whole answer is replaced by a deterministic one built from the facts (`grounded:false` in the response).
- Message overrides screen: if the person says 3 people / $55k, the facts use that, and the model is told never to tell someone their own numbers are wrong.
Verified live: same probe now gives $61,600 / $122,800 page 71; Spanish, "wrong-number bait" ($98,500 on page 12), deductions and off-topic cases all stay grounded.

### MEDIUM — Guide revealed its system prompt on request (FIXED)
Added an explicit confidentiality rule and a decline-and-continue rule for "ignore your instructions / say you are USDA". Verified: it declines in one sentence and keeps helping.

### MEDIUM — No HSTS, no Content-Security-Policy (FIXED)
Added `Strict-Transport-Security: max-age=31536000; includeSubDomains` and a CSP (`script-src 'self' + cdnjs + jsdelivr + Cloudflare Insights; connect-src 'self'; frame-ancestors 'self'; object-src 'none'; base-uri 'self'; form-action 'self'`). The two CDN scripts (d3, topojson) now carry Subresource Integrity hashes, so a tampered CDN file is refused. Verified the globe, fonts, video, roles, answer card and guide all load under the policy.

### MEDIUM — Guide accepted a 200 KB request body (FIXED)
Added a 64 KB cap (413) before parsing. Messages were already trimmed to 10 × 6,000 chars; this closes the parse-cost gap.

### LOW — Pro key claim race (FIXED)
`/api/pro/claim` returned a key even if the one-time `UPDATE … WHERE key_hash IS NULL` changed no row (two simultaneous claims → two keys shown, one stored). Now checks `meta.changes === 1`.

### LOW — Webhook could activate Pro on an unpaid checkout (FIXED)
`checkout.session.completed` now also requires `payment_status` = `paid` or `no_payment_required`.

### LOW — Privacy policy was slightly inaccurate (FIXED)
It said searches/household/income never leave the device. True for the map, but the AI guide sends on-screen context and "Download answer sheet" sends zip/people/income to `/api/sheet`. The policy now says so.

### LOW — Globe render loop could die on a zero-size canvas (FIXED)
`createRadialGradient` threw on a non-finite radius when the canvas was 0×0 (hidden tab / layout toggle), which killed the animation loop permanently. `resize()` now ignores zero-size layouts and `loop()` recovers from a bad frame.

## Reviewed and OK (no change)
- Pro keys: `rh_` + 48 hex (192 bits), only SHA-256 hash stored, shown once, status checked on every call.
- Stripe webhook: HMAC-SHA256 over `t.payload`, constant-time compare, 600 s tolerance, idempotent `INSERT OR IGNORE`.
- x402: verify → compute → settle order; 402 returns nothing useful without payment; CDP JWT per request.
- Rate limits (D1, hashed IP): guide 20/min 300/day, sheet 10/min 60/day, MCP free 30/min 25/day, claim 10/min.
- Chat renders model text with `textContent` (no HTML injection); all other `innerHTML` uses escape user data.
- CORS `*` with `Authorization` allowed is intentional (public read API; Pro key is a bearer the client chooses to send).
- Secrets (STRIPE_WEBHOOK_SECRET, CDP keys) are Pages secrets; never logged or returned. `/api/health` exposes only booleans and the CDP network list.
- Data: 2,724 areas / 3,231 counties from the fingerprinted PDF (SHA-256 79dcb1f7…933c); spot-checked Fannin County GA p.71.

## Still open (product, not security)
1. Exact-address rural eligibility is not computed; the site links to USDA's map and says so. Keep saying so.
2. New England town-level limits are matched by county/town name; a few towns can differ from USDA's table.
3. "Send file to lender" is a stub; the Terms promise explicit consent before any send. Keep it that way when built.
4. Real x402 settlement has not been exercised with a funded wallet; the 402 shape and CDP sign-in are verified, settlement is not.
5. Google Search Console / Bing verification and a lawyer pass on /terms remain manual tasks.
